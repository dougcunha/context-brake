# T07 — Estimated readings keep the recorded window after a reset

## Outcome

After `/clear`, `/compact`, or a new session, when the reading falls back to the estimate, the telemetry block shows the window recorded by the bridge (for example `tokens=15150/1000000 source=estimated`) instead of `contextWindowCeiling`.

## Requirements

- With a recorded status line window and no non-stale token reading, `readZone` returns `source: 'estimated'` and `windowTokens` equal to the recorded window (FR-06, OBJ-01).
- Without `statusline` lines and without a harness window, the result equals PRD 2.1's (OBJ-03).
- An in-process harness that reports `contextWindow` with `tokens: null` gets its window on the estimated path; `usage-resolver.test.ts` covers it.
- The window comes from the harness-reported reading, else the status line, else the ceiling, even when the token reading is stale after a reset.
- `percentage` and `zone` are computed over the same window.
