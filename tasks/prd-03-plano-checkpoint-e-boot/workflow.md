## Exception HIL: T05 compaction delivery

- **Decision:** Approved as `DEC-EX-T05` on 2026-09-21. The recommended correction below is the current contract.

- **Evidence:** [Cursor hooks](https://cursor.com/docs/hooks) documents `sessionStart.additional_context`, but `preCompact` only has `user_message` and no `postCompact`. [GitHub Copilot hooks](https://docs.github.com/en/copilot/reference/hooks-reference) marks `preCompact` output unprocessed; `sessionStart.additionalContext` is for a new or resumed session. The feature research now records both limits. Claude Code and Codex CLI document a session-start event after compaction; Pi and Oh-My-Pi document an in-process post-compaction event and `before_agent_start` message injection.
- **Impact:** T05's acceptance line requiring boot delivery after compaction on every supported harness, and RF9's unqualified compaction promise, cannot be verified for Cursor or GitHub Copilot CLI. Emitting a boot from their `preCompact` response would claim undocumented behavior; injecting on a later tool event would miss the first model call after compaction. The approved `DEC-02` also needs a Cursor `session_id` parser correction to reach documented `sessionStart` payloads.
- **Recommended correction:** Keep `session_boot: supported` for new sessions in all six named harnesses. Implement compaction delivery only for the documented channels (Claude Code, Codex CLI, Pi, Oh-My-Pi). State the Cursor and GitHub Copilot CLI compaction limit in the PRD, TechSpec, T05/T09 acceptance, and QA evidence; preserve the protocol-file fallback. Accept both Cursor `session_id` and `conversation_id` on `sessionStart`. This changes the product guarantee and therefore needs exception HIL.
- **Alternative:** Keep the current guarantee and leave T05 blocked until those vendors document a post-compaction context channel or a verified capture proves one. No unconfirmed capability will be implemented.
