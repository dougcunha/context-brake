## Solution summary

The restart becomes a harness-neutral flow in `src/core` with three ports: the restart host (facts, open a session, seed, notify, log), the guard store, and the handoff store. The Claude Code mod becomes one adapter of that flow without changing its observable behavior. Pi, Oh-My-Pi, and OpenCode get a second in-process file, installed only with automatic restart on, that implements the same ports. It ships only for harnesses where the FR-06 probe verifies both opening a session and seeding it from the end of a turn. Every other harness gets the semi-automatic restart. The existing reset notice names its new-session command where a notice channel exists, and the existing session-start injection delivers the resume instruction.

The markdown handoff adds a third restart mode next to "off" and "snapshot skill". With `autoRestart` on and no `snapshot.command`, the zone action at and above the trigger zone asks for `.context-brake/handoff.md` and the marker. The session-start path is the only deliverer: it claims the pending handoff by moving it to `.context-brake/handoffs/<timestamp>.md`, prunes the archive to 10 files, and injects an instruction naming the archived path. A harness without session-start injection whose probe passes carries the same instruction in its seed. A restart in handoff mode requires a handoff written after the current turn started.

Flow, handoff mode, automatic harness: the post-tool hook renders the handoff action from `RED` on (CMP-02). The agent writes `.context-brake/handoff.md` and ends its reply with the marker. The harness's restart adapter (CMP-08 or CMP-10) sees the turn end and calls `handleTurnEnd` (CMP-07). It gathers stand-down facts, the guard state, `pendingSince()`, and the turn start, and the policy decides. On `restart`, the flow logs `RESTARTED` and opens the new session with the seed. The new session's start event reaches `handleSessionReset` (CMP-04), which claims the handoff and injects the resume instruction. On OpenCode, which has no `session_boot`, the flow claims before opening and puts the instruction in the seed.

Flow, semi-automatic harness: the same action and marker. Codex CLI, Pi, and Oh-My-Pi (before a passing probe) show the reset notice naming `/new`. The person starts a new session, whose start event claims and delivers as above.

## Contracts and data

- **Telemetry action (agent-facing, versioned block `[ContextBrake v3]`):** new text for `mode = handoff` only, `save handoff to .context-brake/handoff.md, end reply with [REQUEST_SESSION_RESET]` (DEC-01). The whole block stays within the 60-token budget (`tests.md`); the test asserts the exact block for `RED` and `CRITICAL`.
- **Resume text (agent-facing, `[ContextBrake resume v1]`):** new variant `[ContextBrake resume v1] Read ".context-brake/handoffs/20261007T120000.000Z.md" and continue the previous work from it.` The existing `Run "<resumeCommand>" before continuing.` variant is unchanged.
- **Seed text:** `ContextBrake: this session was restarted automatically. Continue the previous work from the state it recorded.`, followed on a harness without `session_boot` by a blank line and the resume text.
- **Handoff files:** `.context-brake/handoff.md` (written by the agent, any markdown); archive `.context-brake/handoffs/<UTC timestamp>[-n].md`, at most 10 files, oldest deleted by name order.
- **Restart log v2** (`.context-brake/runtime/restart/<harness>/<sessionId>.json`): `v: 2` (literal), `harness` (`HarnessId`), `componentVersion` (string, the mod or restart-module version), `harnessVersion` (string, `"unknown"` when the host does not expose it), `records` (array ≤ 50 of `{ at: ISO string, code: RestartReasonCode }`). Zod strict. v1 files are ignored by doctor (DEC-PD-03).
- **Reason codes:** add `SKIP_HANDOFF_MISSING`, `SKIP_HANDOFF_STALE`; rename `ERROR_CLEAR_REJECTED` → `ERROR_RESTART_REJECTED`.
- **Finding codes (free strings in the published schemas):** add `AUTO_RESTART_MODE` (init, per harness), `AUTO_RESTART_HANDOFF` (doctor, project), `AUTO_RESTART_HANDOFF_KEPT` (remove and `--no-auto-restart`, project). Existing `AUTO_RESTART_*` codes gain a `harness` other than `claude-code`. Neither `schemas/*.json` nor exit codes change; `npm run schemas:check` proves it.
- **Configuration:** unchanged. `autoRestart` presence remains the switch; `maxConsecutiveRestarts` applies to every harness.

## Integrations and interfaces

- **Claude Code mod:** same events (`turn.complete`, `turn.start`, `tool.call`, `prompt.submit`), same `/clear` and seed, new log dir and v2 log. Its simulated-host tests keep their assertions except the log path, the renamed code, and the new handoff gate (FR-05).
- **Pi and Oh-My-Pi restart extension (if the probe passes):** registers the `context-brake-restart` command and subscribes to `agent_start` (turn start), `input` (typed-prompt reset), `tool_result` (progress count), and the turn-end event the probe confirms (`message_end`/`agent_end` for Pi, `session_stop` for Oh-My-Pi). On a passing decision it dispatches the command, whose handler calls `ctx.newSession({ withSession })` and seeds through `sendUserMessage`. Failure policy: any error logs `ERROR_INTERNAL` or `ERROR_RESTART_REJECTED`, rolls the guard back, and leaves the session intact (NFR-01). Timeout: none added; the handler awaits only the restart calls.
- **OpenCode restart plugin (if the probe passes):** subscribes through `event` to the turn-end and busy events the probe records and reads the last assistant text through the SDK call the probe records. On a passing decision it claims the handoff, then calls `tui.executeCommand({ command: "session_new" })`, `tui.appendPrompt(seed)`, and `tui.submitPrompt()`. Same failure policy.
- **Process-hook harnesses:** no new events. Codex `Stop` keeps the notice path, now with `endsWithResetSignal`. `SessionStart`/`sessionStart` delivers the claimed handoff.
- **CLI:** `init --auto-restart` accepts any target set with a restart mode; `init --dry-run` lists the ignore file and the restart files. `doctor` and `remove` add the findings above. Output follows `cli-output.md`.

## Errors, security, and recovery

- Errors and edges: `claim` on a missing file returns `null`; on any other I/O error the session-start hook follows the failure policy (neutral response, `errors.jsonl`) and the handoff stays pending for the next start. A handoff written while restart is off is neither requested nor delivered (NFR-05). Two simultaneous starts: one claims, one gets `null`. Timestamp clash: numeric suffix. A session open or seed that fails logs `ERROR_RESTART_REJECTED`. Only on OpenCode was the handoff already claimed; there the failure notice names the archived path so the person can point the next session to it.
- User files and sensitive data: the handoff never leaves `.context-brake/`; ContextBrake reads only its mtime and moves it (NFR-04). The ignore file keeps it out of Git (DEC-12).
- Concurrency and idempotency: rename-based claim (DEC-02). `init` twice plans no change the second time.
- Rollback or reversal: `init --no-auto-restart` removes every restart artifact and keeps handoffs; reverting the commit restores PRD-11 behavior (no migration, DEC-PD-03).
